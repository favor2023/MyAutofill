# 我的本地记忆填充 (MyAutofill)

一个极简的 Chrome 扩展：**记住输入框上次填过的内容，下次鼠标点一下就能填回去**。

完全离线、不联网、不上传任何数据。

---

## 它解决什么问题

内部工作网站要反复手打同一串编号、单号、地址、备注。浏览器的自动填充管不了这些自定义表单，每次都得重新敲一遍。

这个扩展的做法很简单：你在输入框里填完东西、鼠标点到别处，它就悄悄把内容存在浏览器本地。下次点击同一个输入框，下方弹出一个小菜单，鼠标点一下候选项就填进去了 —— **全程不用碰键盘**。

---

## 功能

- **记住上次输入** —— 每个输入框独立记忆，最新填的排最前，最多保留 5 条。
- **鼠标点击填入** —— 点击输入框弹出候选列表，点一下即填入。
- **纯本地存储** —— 数据存在 `chrome.storage.local`，扩展没有申请任何网络权限。
- **区分网站与字段** —— A 网站填的内容不会跑到 B 网站；同网站不同输入框也分开记。
- **自动去重** —— 相同内容只保留一条，不会无限增长。
- **兼容现代前端** —— 主动触发 `input` / `change` 事件并使用原生 value setter，Vue / React 写的受控表单也能正确识别。
- **支持多种字段** —— 文本框、搜索框、密码框、数字框、邮箱、多行文本，以及 `contenteditable` 富文本。
- **支持 iframe 与 Shadow DOM** —— 内嵌表单和 Web Component 表单同样生效。

## 安装

不需要从商店安装，直接加载本地文件夹即可。

1. 打开 Chrome，地址栏输入 `chrome://extensions/` 回车。
2. 打开右上角的 **开发者模式 (Developer mode)** 开关。
3. 点击左上角 **加载已解压的扩展程序 (Load unpacked)**。
4. 选择包含 `manifest.json` 的文件夹（例如 `MyAutofill`）。
5. 完成。插件会静默运行，无需固定到工具栏。

> 修改代码后，必须回到 `chrome://extensions/` 点击插件卡片上的 **重新加载 (↻)**，并**刷新目标网页**，新代码才会生效。

Edge、Brave 等 Chromium 内核浏览器步骤相同，把 `chrome://extensions/` 换成 `edge://extensions/` 即可。

---

## 使用

1. 打开你的内部网站。
2. 在输入框里正常输入内容，例如 `A-001`。
3. 鼠标点击页面空白处（让输入框失去焦点），内容自动存入本地。
4. 刷新页面，或关掉重开。
5. **只用鼠标**点击那个输入框，下方弹出候选菜单。
6. 点击候选项，内容自动填入。

按 `Esc` 可以关闭候选菜单。

## 文件结构

```
MyAutofill/
├── manifest.json   # 扩展清单（权限、注入规则）
└── content.js      # 全部逻辑：记忆、弹出、填入
```

整个扩展只有这两个文件，没有依赖、没有构建步骤。

## 工作原理

| 环节 | 做法 |
| --- | --- |
| 记忆时机 | 监听 `focusout`，延迟 200ms 保存，避开"点击候选框也触发失焦"的冲突 |
| 存储位置 | `chrome.storage.local`，键名 = `域名 + 路径 + 字段签名` |
| 字段签名 | 依次尝试 `name` → `id` → `aria-label` → `placeholder` → `data-*` → DOM 结构路径，取第一个可用的 |
| 弹出时机 | 监听 `focusin`，延迟 150ms 显示，避免和浏览器原生自动填充打架 |
| 填入方式 | 用 `HTMLInputElement.prototype` 上的原生 value setter 写值，再派发冒泡的 `input` / `change` 事件 |
| 定位方式 | `position: fixed` 贴合输入框；下方空间不足时自动翻到上方 |

之所以用原生 setter 而不是直接 `el.value = x`，是因为 React / Vue 会在 value 上挂自己的追踪器，直接赋值会被框架判定为"值没变"从而忽略，导致填进去又被回滚。

## 隐私

- 只申请了 `storage` 一个权限，**没有** `host_permissions`，**没有**网络请求。
- 所有数据仅存于本机浏览器配置目录中，不经过任何服务器。
- 卸载扩展或在 `chrome://extensions/` 中移除，数据即随扩展一起清除。

想手动清空记录：打开 `chrome://extensions/` → 该插件「详情」→ 找到存储相关选项，或在 DevTools 中清除 `chrome.storage.local`。

## 排查问题

扩展内置了调试开关，排查时先打开它。

打开 `content.js`，把第 5 行改成：

```javascript
const DEBUG = true;
```

然后到 `chrome://extensions/` 重新加载插件，刷新目标网页，按 `F12` 打开控制台。你会看到形如 `[记忆填充] 已注入 <网址>` 的日志。

### 对照日志定位

| 现象 | 原因与处理 |
| --- | --- |
| 控制台看不到任何日志 | 脚本未注入。常见于跨域 iframe 或页面 CSP 限制。检查 F12 控制台的红色报错 |
| 有「已注入」但没有「命中 N 条」 | 内容没被保存。可能是输入框并非真实 `<input>`（如自定义组件），或失焦事件被页面拦截 |
| 有「命中 N 条」但屏幕上没有弹出框 | 定位被遮挡。可反馈截图，需要把节点挂到 `documentElement` 上 |

### 其他注意事项

- **必须刷新页面**后才生效，content script 只在页面加载时注入。
- 键名包含**路径**，所以同一系统下不同 URL 页面分别记忆。若希望同域名下全部页面共用一份记录，把 `getInputKey` 中的 `location.pathname` 去掉即可。

## 已知限制

- 富文本编辑器若使用自定义实现（非 `contenteditable`），可能无法识别。
- 原生 `<select>` 下拉选择框不在此扩展处理范围内，它只处理文本类输入。
- 记录上限为每个字段 5 条，超出自动淘汰最旧的。
